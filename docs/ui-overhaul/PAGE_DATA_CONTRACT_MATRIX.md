## Typed integration contracts (proposed versioned UI boundary)

The names below version the UI boundary; they do not claim a persisted or deployed API version. Implementing PRs should add runtime schema validation and fixtures before wiring live source. Every response carries a discriminated status (`ready`, `empty`, `partial`, `locked`, `unavailable`) and source metadata from its real source; do not fabricate defaults for missing values.

### `tdr.compare-ui.v1` — PR 8

- **Request:** `trimIds: CanonicalTrimId[]` (2–4 distinct IDs); optional legacy URL parse accepts repeated `trims` and queued `models`, maximum four combined. Preserve exact canonical trim selection; a model deep link queues a picker and is not silently promoted to an arbitrary trim.
- **Response:** current runtime-compatible `selected`, `missing_selection`, `groups`, `quota` and optional `anonymous` fields. Each row retains `key`, `label`, values in selected-trim order, different flag, `comparisonMode`, `comparable`, `bestIndexes`. Qualifier context, units and source/provenance must come from Vehicle Master fact payload/registry; where the current DTO omits evidence needed for truthful display, the adapter reports it missing and the PR adds an explicit accepted field rather than inferring.
- **Authority/security:** public picker APIs may return catalog choices; result API authenticates and consumes exactly one server-side quota per logical compare action. No browser-supplied quota or winner calculation.
- **Acceptance:** existing `lib/compare-winners.ts` golden cases, four trim cap, deep-link/URL round-trip, expired/invalid IDs, missing/UNKNOWN values, incomparable qualifier rows, ties, 401/429 and non-leakage.

### `tdr.pricing-ui.v1` — PR 9

- **Request:** read-only plan catalog plus authenticated `planCode` checkout action. No client-selected price amount, provider or entitlement tier.
- **Response:** `PLAN_CATALOG` entries (`planCode`, tier, product, interval, THB/month, billed THB/interval), feature matrix from `lib/access-policy.ts`, checkout readiness only as a server-confirmed configured/unconfigured state. Billing status is fetched from `/api/billing/status`; success redirect is not proof of payment.
- **Authority/security:** `lib/plans.ts`, `lib/access-policy.ts`, `lib/billing.ts`, verified Supabase Auth and Stripe webhook. Exact Stripe provider Price object/env values remain deployment facts.
- **Acceptance:** all displayed amounts match catalog; monthly/quarterly/annual semantics; Enterprise contact-only; configuration missing fails closed; no changes to provider/webhook/tier code; account and upgrade deep links preserve auth redirect safely.

### `tdr.market-ui.v1` — PR 11

- **Request:** supported Ice `dimension`, period/window, comparison and filters as explicitly accepted by the selected Ice reader; no UI-only dimensions. Public and member access are separate operations.
- **Response:** reader-owned release ID, source/package, exact period/window, source grain, units, market denominator, mapped/unmapped/excluded units, identity-link version/status, rows and comparison/trend only where reader supports them; tier/allowed actions/quota returned or resolved server-side. Unknown values remain unknown. These fields are a **minimum required contract**, not a claim that all are present in PR #246's current route payload.
- **Authority/security:** Ice package and approved scoped links for registrations; Vehicle Master for canonical model identity and canonical segment/body; server access policy for member tier/quota. Public new UI never falls back to `getPublicMarket()` or `registration_reporting_source` after an Ice error.
- **Failure behavior:** unsupported filter/dimension is a typed error, never silently dropped; no release or period yields `empty`/`unavailable`; partial identity coverage stays visible; access denial yields `locked`; stale/error response never re-labels legacy data as Ice.
- **Acceptance:** released package/release provenance, denominator reconciliation, supported-filter matrix, class scope, owner link state, 401/403/429, no legacy fallback, parity with independent Ice acceptance. R6/R7/R8 gates remain outside UI completion.

## Shared state and provenance rules

- `loading`: skeleton must reflect the actual card's layout and avoid a made-up zero.
- `locked`: server-derived entitlement response; sensitive values omitted from HTML/JSON, not blurred client-side after delivery.
- `empty`: successful response with no qualifying rows, distinct from unavailable or denied.
- `partial`: include a specific coverage numerator/denominator and unmapped/excluded treatment from the source. Do not reuse the historic August 81% figure as a current universal threshold.
- `error/unavailable`: show retry/next action without switching source, period, identity grain or entitlement tier.
- Every data contract defines source release/ref, observed/effective date, period, units and grain where meaningful. A field unsupported by the source remains `UNKNOWN`; no sibling/segment/price inference.
- Cross-cutting URLs preserve valid existing incoming routes/parameters until a reviewed redirect proves parity. APIs stay stable unless the contract-owning PR adds a backward-compatible versioned adapter.
