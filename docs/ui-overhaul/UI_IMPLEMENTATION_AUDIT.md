## Current design and runtime quality findings

- `design/migrated.json` records strict token-check coverage for layout/shell, shared components, Models, Brands, Search and Upcoming card boundary. It is not a page-completion registry and does not show Compare, Pricing/Auth, Home #173, Market/Analysis or Upcoming full routes accepted.
- `design/PAGES.md` and its reference mockups remain product design input; mockup numbers, text, prices, fake car models, charts and launch dates are not data evidence.
- `app/page.tsx` currently shares `PLAN_CATALOG`; `lib/plans.ts` is Stripe-backed. The old Data Map/Graft pricing and Omise sections must not be used as current copy.
- `app/compare/page.tsx` uses browser session discovery, lazy public pickers and a server compare endpoint. Preserve those trust boundaries; its winner semantics are server/library-owned.
- Market current and proposed paths are separate: main public snapshot is legacy; main member interaction is legacy; PR #246 has Ice code on an unmerged branch. No new UI should select/fallback between them silently.
- Model/trim data pages use canonical Vehicle Master read helpers and spec field registry. ICE registrations are not canonical vehicle attributes. The exact UNKNOWN state and source evidence must remain visible where relevant.
- `app/research` and `app/api/research/read` are live code surfaces for public preview and protected content. A proposed new `analysis_reports` schema is not a prerequisite unless the existing shape fails the agreed UI contract.
- Upcoming previews in PR #220 are static, contain synthetic content and disabled controls. They establish no server validation, authorization, DB, accessibility, deployed route, or visual QA.
- No browser-rendered screenshot, Lighthouse/accessibility audit, Vercel preview URL, production runtime/flag, Supabase schema/ACL or actual plan Price ID was independently checked for this audit.
