# แผนงาน: ระบบข่าว (News) บนเว็บ TDR (16 ต.ค. 2569)

สถานะ: การตัดสินใจอยู่ใน `docs/MERGE_DECISIONS.md` P3 · **แผน ยังไม่มีโค้ด** · ไม่ใช่ใบสั่งงาน (`execution.enabled=false`) · ทุกขั้นต้องมี owner go แยก

## 1. ที่กี้ตัดสินแล้ว
- `/news` เป็นหน้าข่าวใหม่ · event stream เดิมย้ายไปที่อื่น (ปลายทางยังไม่ตัดสิน)
- เรียงข่าว + tag ที่แอดมินสร้างเอง · ป้ายข่าวด่วนตัวอักษรแดง (token) ไม่ใช้ emoji · หมดอายุอัตโนมัติ
- หน้าข่าวมีหัวข้อ ภาพ เนื้อหา และลิงก์ไปหน้ารุ่น/เทียบรุ่น
- เขียนและเผยแพร่โดยกี้คนเดียว (ไม่มี workflow ตรวจ)

## 2. ข้อจำกัดจาก repo
- ข่าวเป็น editorial อ้างอิง ID รถมาตรฐานได้ แต่ **ห้ามนิยามข้อเท็จจริงของรถเอง** (AGENTS.md) · ไม่แตะ `automotive/vehicle_master/`
- migration ใหม่: กี้รัน SQL เอง · เลขต้องไม่ชนกัน (ตอนเขียน v69/v70 ยังไม่ apply; เช็ก `main` และ PR ที่เปิดอยู่ก่อนเลือก) · ตามหลักการจองเลขใน MERGE_DECISIONS ห้ามสร้างเลขเปล่า
- หนึ่ง PR ต่อหนึ่งงาน บน `feat/news-*` · สีผ่าน token เท่านั้น · ไม่มีตรรกะข้อมูล/สิทธิ์/ชำระเงินใน PR ออกแบบ

## 3. สิ่งที่มีแล้วและใช้เป็นแบบได้
- `research_articles` (migration v38): slug unique, status, published_at, RLS ปิด public → แม่แบบตารางข่าว
- admin: `saveResearchArticle`, `uniqueSlug`, ฟอร์ม `Field/Select/TextArea` · Supabase Storage ใช้อยู่แล้ว → ใช้เป็นแบบอัปโหลดภาพ
- ปลายทางลิงก์: `/models/[slug]` · `/compare` รับ `?trims=<trim id>` และ **`?models=<model id>` อยู่แล้ว** (ถ่ายโอนจาก CompareTray: โมเดลที่ส่งมาจะเปิดตัวเลือกรุ่นย่อยของแต่ละรุ่น แล้วรอผู้ใช้เลือกเอง ไม่เลือกให้)

## 4. โมเดลข้อมูล (ข้อเสนอ)
- `news_articles`: id, slug, title_th, excerpt_th, body (ข้อความ + โทเค็นลิงก์), cover_image_path + cover_alt + credit, status (draft/published), published_at, is_breaking, breaking_until, seo_title, seo_description
- `news_tags` (kind: brand/model/topic, entity_ref ผูกกับแบรนด์/รุ่นมาตรฐานได้) + `news_article_tags`
- `news_article_entities` (entity_type/entity_id) ใช้สร้างกล่อง "ที่เกี่ยวข้อง"
- ไม่ยุ่งกับตาราง `events` เดิม (event = ข้อเท็จจริงเชิงข้อมูล, news = บทความ)

## 5. ลิงก์ในเนื้อหา (super link)
- `[[model:<slug>]]` → หน้ารุ่น · `[[compare:<slug>|<slug>]]` → ปุ่มเทียบรุ่น
- หลังบ้านมีปุ่ม "แทรกลิงก์รุ่น" (ค้นหา → แทรกโทเค็น) และตรวจตอนบันทึกว่ารุ่นมีอยู่จริง · ตอนแสดงผลแปลงเป็นลิงก์ด้วย slug ปัจจุบัน
- ลิงก์เทียบรุ่น: ใช้ `/compare?models=<model id>&models=<model id>` ที่มีอยู่แล้ว (ผู้อ่านเลือกรุ่นย่อยเอง) หรือเลือกรุ่นย่อยเริ่มต้นให้ ซึ่งต้องมีเกณฑ์ → **กี้เลือก** (ค่าเริ่มต้นที่เสนอ: ใช้ `?models=`) · ห้ามแก้ compare ในงานข่าวนอก PR แยก
- กล่อง "ที่เกี่ยวข้อง": ดูหน้ารุ่น · เทียบกับคู่แข่ง (เกณฑ์ชัด เช่น เซกเมนต์/พลังงานเดียวกัน ไม่อ้างว่าแทนกันได้จริง)

## 6. ข่าวด่วนและ SEO
- ป้าย "ด่วน" สีแดงผ่าน token · แสดงเมื่อ `is_breaking` และไม่เลย `breaking_until` (เริ่มต้น 48 ชม.) · หน้ารายการเรียงข่าวด่วนไว้บน ไม่เกิน 3 ข่าว
- เรนเดอร์ฝั่งเซิร์ฟเวอร์ · metadata ต่อบทความ · canonical · ภาพ OG · JSON-LD NewsArticle · news sitemap · หน้ารวมตาม tag
- ภาพต้องมี alt · ลิขสิทธิ์ภาพจากผู้ผลิต: เก็บ credit เป็นฟิลด์

## 7. ลำดับ PR (หนึ่ง PR ต่อหนึ่งงาน)
0. เอกสาร (PR นี้): บันทึกการตัดสินใจ + แถว News ใน GRAFT_PLAN
1. ฐานข้อมูล + หลังบ้าน: migration (กี้รัน) + ฟอร์มเขียนข่าว, tag, อัปโหลดภาพ, ตัวแทรกลิงก์รุ่น
2. หน้าสาธารณะ: `/news`, `/news/[slug]`, `/news/tag/[slug]`, ป้ายด่วน, ย้าย event stream เดิม
3. SEO + ลิงก์ลึก: metadata, JSON-LD, sitemap, กล่อง "ที่เกี่ยวข้อง"
4. (ภายหลัง) แถวข่าวล่าสุดบนหน้ารุ่น/`/market` ถ้ากี้ต้องการ

## 8. เรื่องที่ยังต้องตัดสิน
1. event stream เดิมย้ายไปที่ไหน · 2. ลิงก์เทียบรุ่นในข่าว (ข้อ 5) · 3. แหล่งภาพข่าวและรูปแบบเครดิต · 4. แสดงข่าวล่าสุดบน `/market` และหน้ารุ่นหรือไม่ · 5. ตำแหน่งข่าวในเมนู
