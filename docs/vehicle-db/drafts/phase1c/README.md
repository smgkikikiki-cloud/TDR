# Phase 1C BASIC identities — offline PostgreSQL acceptance

This directory contains an unnumbered, nondeployable draft of BASIC identity
storage and its governed structural RPC. The only executable path here is the
acceptance runner against an ephemeral local Docker database. The existing
Structural Identity Writer remains the planner; `basic-identity-db-compat.ts`
remains the serializer contract, and its application adapter remains fail-closed.

Run `npm run check:phase1c-postgres-acceptance`. The runner pins PostgreSQL
16.10 by image digest, uses `--network none`, stores PGDATA only in disposable
container tmpfs, publishes no port, replays repository SQL through v57–v64 in
dependency order, and removes the container even after a failed assertion. It
loads collision tokens and required brand fixtures from the frozen read-only
Vehicle Master snapshot. No shared database URL, staging/production endpoint,
or remote service is read by the runner. The report at
`postgres_acceptance_report.json` is generated by that command.

The successful run creates the eight preflight-valid model identities
(47,109 registration units) as BASIC rows. Their lifecycle, generation,
segment, body, price and seed/release fields remain SQL NULL. They are absent
from `current_vehicle_models`, pass the existing CATALOG parity/seed/engine
checks, and can be selected only through a private lookup. It also verifies
same-receipt retry, changed-payload idempotency rejection, fresh and stale alias
revision CAS, expired-capability rejection, canonical and normalized-alias
collision rejection, successful RPC calls through a dedicated non-superuser
approver login, denied direct unprivileged authenticated DML and service-role
RPC invocation, forged request fields, SERIALIZABLE enforcement, and rollback after
an injected second-item failure. A compensating alias revert restores its prior
alias payload at a new revision and is idempotent on retry; structural creates
are hidden only when the expected revision has no active dependents. The eight
groups' Ice body/segment classifications are stored only under the append-only
raw observation evidence; canonical BASIC model fields remain NULL. A concurrent
two-session PostgreSQL create race allowed only one normalized identity token
owner, then soft-hid its disposable test row.
Ford Ranger Raptor remains held by the existing writer because the frozen
catalog alias `ford.ranger_double_cab` owns `ranger raptor`.

## Not a production activation

The local RPC requires an isolated test fixture to issue its bound, expiring
capability; this is not a deployed admin session or an approval of any identity.
No production/staging DDL or write was attempted. Do not number or deploy these
files from this PR. Remaining production dependencies include:

- Independent QA and owner adoption of the BASIC/catalog, provenance, and
  private Market Analysis serving semantics.
- A fresh production v57–v64/schema-and-ledger reconciliation and resolution of
  C02. The frozen 2026-10-13 snapshot is not a live revision token.
- A separately reviewed trusted role/capability issuer and session-to-actor
  binding for the actual DB gateway; private schema/RPC ACL review.
- A production-compatible structural revision/audit design that does not rely
  on the retired `canonical_write_commands` FK, plus separately approved
  migration allocation/application.
- Separate C01/R6 authorization and scoped crosswalk implementation. This
  structural RPC rejects links and all price operations.

The PR changes no `portfolio.plan.json`, C01/C02/R6 gate, migration number,
deployment, or production/staging data.
