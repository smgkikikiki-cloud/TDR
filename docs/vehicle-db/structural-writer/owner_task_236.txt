## Phase B — Implement the Structural Identity Writer

After completing the audit, implement the smallest coherent Vehicle DB v3 Phase 1 structural writer within the existing architecture.

Support these operations:

- `CREATE_BRAND`
- `CREATE_MODEL_BASIC`
- `UPDATE_MODEL_ALIAS`
- `LINK_ICE_MODEL_GROUP_BY_REG_TYPE`, subject to the separate R6 authorization boundary

Required functionality:

1. Validate Brand foreign keys and canonical identity uniqueness.
2. Reject duplicate Model IDs, incompatible aliases and uncertain model-vs-trim identities.
3. Use TDR Vehicle Master Segment and Body Type as canonical authority. Ice classifications remain raw evidence only.
4. Preserve UNKNOWN fields when no approved TDR evidence exists.
5. Enforce server-side permissions: AI/agents can propose structural changes, not approve or directly apply them.
6. Support deterministic planning, idempotency, optimistic revision checks, audit logging and compensating revert.
7. Use existing canonical Vehicle Master tables and existing compatible audit infrastructure rather than creating another master.
8. Keep Ice registrations separate from Vehicle Master, linked only through authorized, class-scoped Crosswalk mappings.

If real database integration needs a new migration, prepare the design and tests without assigning or applying a migration number until C02 is resolved.

Do not use `vm_apply_price_changes` or the retired `canonical_input_batches` path for identity creation.
