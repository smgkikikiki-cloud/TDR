## Server/RPC boundary

The future governed RPC accepts validated structural intents and an idempotency key. It must re-read and lock the current master/alias/source-scope rows, recompute or verify the plan against the exact current snapshot, validate Brand FK + ID/name/slug/alias uniqueness, and compare expected revisions inside one transaction. Trusted snapshot classification and alias-equivalence evidence must resolve to the approved existing TDR observation/inbox/audit records for the exact identity; they cannot be supplied as client approval flags or inferred from Ice/siblings. A names/aliases uniqueness race needs SERIALIZABLE semantics or deterministic per-brand locks plus a database-backed normalized-token uniqueness guard; a read-before-write check alone is insufficient.

`actor_kind`, approval flags and R6 permission must not be trusted from the items JSON. The server verifies the existing TDR admin session and supplies a protected authorization capability bound to actor, operation set, payload hash, expiry and nonce; the RPC verifies that capability or an equivalently trusted DB identity. Agent service credentials have propose-only scope. No grant of direct identity DML is part of this design. The new structural RPC must not reuse `vm_apply_price_changes` or `canonical_input_batches`.

The transaction commits master rows, structural observation, inbox approval, audit and idempotency receipt together, or none of them. Rollback cannot leave half-created identities/aliases or a falsely approved card. A compensating revert requires current revisions and payload hashes to still match the logged after-state. Creates are hidden, never hard-deleted; active child/link dependencies block hiding. Reverted links become PENDING unless a prior authorized state is restored. A second revert does nothing. Revert cannot mutate frozen owner source evidence.

The TypeScript `TransactionalIdentityStore` is a contract, not a production database transport. `lib/vehicle-engine/basic-identity-db-compat.ts` serializes eligible plans from the existing writer into a future single-RPC request, but `BasicIdentityDbAdapter.submit()` always fails closed, even with hypothetical capabilities or an admin-like transport. The repository currently provides only the fake store and a server session boundary with R6 permanently denied. Real DB acceptance and migration replay tests remain unrun because no structural RPC is deployed and no state-changing SQL is authorized here. See [the dated schema reconciliation](BASIC_IDENTITY_SCHEMA_RECONCILIATION_2026-10-13.md) and [non-executable RPC sketch](drafts/basic_identity_governed_structural_rpc.sql).
