# MERGE_DECISIONS.md — ข้อตัดสินใจการรวม repo TDR กับชุดส่งมอบของ Ice

ผู้ตัดสิน: **กี้** (เจ้าของ repo) · บันทึก 28 ก.ย. 2569 · ไฟล์นี้บันทึกเฉพาะสิ่งที่กี้ตัดสินแล้ว **ห้ามเติมหรือตีความเอง** ถ้าเรื่องไหนไม่อยู่ในนี้ ให้ถามกี้
กฎการออกแบบอยู่ใน `design/DESIGN.md` · ชุดส่งมอบต้นฉบับของ Ice ไม่ได้อยู่ใน repo นี้ (อ้างถึงเป็น "docs/02 ของ Ice" ฯลฯ)

## ตัดสินแล้ว

### ระดับสมาชิก
- **ไม่ล็อกอิน:** ยึดของ repo (`docs/PRODUCT_ACCESS.md` คอลัมน์ "ไม่ล็อกอิน")
- **Free:** ยึด Freemium ของ Ice — 30 วันนับจากยืนยัน OTP, เห็นงวดล่าสุด, เลือกการจำแนก 1 แบบ (จังหวัด / 20 รุ่นแรก / เชื้อเพลิง) แล้วล็อก, ไม่มีส่งออก/คัดลอก, มีลายน้ำ, 1 เบอร์โทร = 1 สิทธิ์
- **Free หลังครบ 30 วัน:** เห็นหน้าเชิญอัปเกรด · **Compare Specs ยังใช้ได้ไม่จำกัด** · Automotive Intelligence และ Analysis Report **เท่ากับคนไม่ล็อกอิน**
- **Pro:** สิทธิ์ตาม Ice — ทุก Panel ย้อนหลังทั้งหมด, เทียบช่วงเวลาได้, สร้าง Info PNG/PDF + Top 10, **ไม่มี CSV**, ลายน้ำชื่อผู้ใช้ในทุกไฟล์ที่ส่งออก
- **Enterprise:** สิทธิ์ตาม Ice — เหมือน Pro + ส่งออก CSV (จำกัดครั้ง/เดือน ค่าตั้งค่า) + 2 บัญชี

### สิทธิ์ของฟีเจอร์ที่มีเฉพาะใน repo
1. **Compare Specs:** กฎเดิมของ repo — ไม่ล็อกอิน 10 ครั้ง/วัน · ล็อกอินแล้ว (Free รวมหลังหมด 30 วัน, Pro, Enterprise) ไม่จำกัด
2. **/market เดิม:** ย้ายเข้า Automotive Intelligence เป็น **Panel 5 "ส่วนแบ่งตลาด"** ใช้กฎ Freemium/Pro ของ Ice แบบเดียวกับ Panel อื่น (เลิกโควตา 5 ครั้ง/วัน และ 12 เดือนของ Free เดิม) · snapshot สาธารณะงวดล่าสุดสำหรับคนไม่ล็อกอินคงไว้
3. **Analysis Report:** ระดับสิทธิ์รายฉบับ (`required_tier`) · ช่วง Freemium อ่านรายงานระดับ Pro ได้ 2 ฉบับ · ไม่ล็อกอินเห็นรายการ + สรุป
4. **ส่งออก PDF:** Freemium ไม่ได้ · Pro/Enterprise ได้และ**มีลายน้ำทุกไฟล์** (เลิก Free 1 ครั้ง/เดือน และ Pro ไม่มีลายน้ำ ของเดิม)

### ราคา (รวม VAT)
- **Pro:** ฿1,099/เดือน · **฿11,490/ปี** (ประหยัด ฿1,698 = 12.9% · เฉลี่ย ≈ ฿958/เดือน)
- เลิกใช้ ฿1,290 / ฿990×3 / ฿790×12 เดิมของ repo
- **Enterprise:** **ไม่แสดงราคา** · ปุ่มน้ำเงิน **"Contact →"** ไปหน้าติดต่อ TDR · **ไม่แสดงเบอร์โทร**

### ชำระเงิน
- **Omise** แทน Stripe (Stripe ไทยไม่รองรับ TrueMoney / ShopeePay / Rabbit LINE Pay) · ชั้น `tdr_entitlements` ที่แยกจากผู้ให้บริการใช้ต่อได้
- ต่ออายุอัตโนมัติในช่องทางที่ทำได้ (บัตร) + **แจ้งเตือนก่อนต่ออายุ/หมดอายุ 7 วันเสมอ** · e-Wallet/PromptPay ให้ลูกค้ากดจ่ายเองหลังได้แจ้งเตือน
- ต้องถาม Omise ก่อนลงมือ: Charge Schedules API "ปิดสำหรับบัญชีที่เปิด 3DS" → บัตร 3DS ตัดอัตโนมัติได้หรือไม่

## ตัดสินแล้ว — แผนงาน (1 ต.ค. 2569, กี้)
รายละเอียดและลำดับงานอยู่ใน `design/GRAFT_PLAN.md` §0
- **การ graft รอบนี้คือการ overhaul:** ยกเลิกสมมติฐานเดิมที่ว่า Market / Compare / Analysis และส่วนของหน้าแรกที่เกี่ยวข้อง "คงของเดิมไว้ก่อนแล้วค่อย overhaul ทีหลัง" · ห้ามเก็บหน้าเก่าหรือ UX เก่าชั่วคราวด้วยเหตุผลนั้น
- **UI แยกจากการย้าย data engine:** บล็อกข้อ 11 (engine ตลาดใหม่) ห้ามต่อ Home/Intelligence เข้ากับ engine เก่า ห้ามคิดตัวเลขเอง และต้องต่อ engine ใหม่ตอนขึ้นจริง แต่ **ไม่ได้ทำให้ UI ต้องรอ** — โครงหน้า ตัวกรอง แท็บมิติ ตัวควบคุมเทียบ กล่อง KPI ตาราง/กราฟ สถานะทั้ง 4 และ responsive ทำตามดีไซน์สุดท้ายได้เลย โดยมีสัญญาข้อมูล (data contract) ที่ชัดเจนให้ engine ใหม่เสียบเข้ามา
- **Compare (PR 8) = overhaul เต็มหน้า** · รักษาความถูกต้องของโควตา, canonical trim identity, ข้อมูลเทียบ, `compare-winners` และ URL/ตัวเลือกที่เข้ามาแบบถูกต้อง · ไม่ต้องรักษาหน้าตาเดิม
- **Market / Intelligence (PR 11) = overhaul เต็ม** · **Analysis (PR 13) เลื่อนขึ้นมาทำเร็วขึ้นได้** รวมสัญญาข้อมูลการ์ดรายงานล่าสุดของหน้าแรก
- **หน้าแรก (PR 5, #173) ยังเป็น draft:** `MarketUpdating` และ empty state ของ Analysis เป็นสถานะชั่วคราว ไม่ใช่หน้าสุดท้าย · ก่อน merge ต้องต่อบล็อก Market กับ engine ใหม่, ใช้ Analysis จริง และเอา placeholder ที่มีเพราะงานอื่นยังไม่เสร็จออกทั้งหมด
- ลำดับที่แนะนำ: PR 6 → 7 → 8 → Analysis → 9 → 10 → 11 (เมื่อมีสัญญา engine ใหม่) → ปิด/rebase PR 5 · ตัวเลขลำดับใน GRAFT_PLAN ไม่ศักดิ์สิทธิ์ ใช้ข้อจำกัดเรื่อง dependency เป็นหลัก · ไม่แตะ Vehicle Master
- **เลข migration (1 ต.ค. 2569):** Upcoming = `v53`, Analysis = `v54` เป็นเลขที่จองไว้ต่อฟีเจอร์เพื่อกันชนกันระหว่าง PR ที่ทำขนาน ไม่ใช่ข้อกำหนดว่าต้อง merge ตามลำดับเลข · ถ้า Analysis merge ก่อน v53 ว่างไว้ชั่วคราว (ห้ามเปลี่ยน Analysis เป็น v53 ตามลำดับ merge, ห้ามสร้าง v53 เปล่า) · Upcoming ใช้ v53 ของตัวเองเมื่อ merge · v54 ต้องไม่พึ่ง schema ของ Upcoming · ถ้ายกเลิก Upcoming ปล่อย v53 ว่างถาวรได้ ห้ามเปลี่ยนเลข migration ที่ merge แล้ว
