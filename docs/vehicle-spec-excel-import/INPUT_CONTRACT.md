# Vehicle Spec Excel Import — Input Contract

Status: implemented / current contract

## Purpose

This is the deterministic Excel/CSV editing surface for existing canonical MarketTrims. It is not an evidence/source ingestion path and the workbook does not contain mandatory source, URL, or observed-at columns.

## Identity

One data row represents one existing MarketTrim.

`canonical_trim_id` is the only placement identity. The template also includes human-readable brand/model/generation/trim/powertrain columns, but the importer ignores those for placement.

Unknown `canonical_trim_id` values are rejected. The importer never creates or fuzzy-matches Brand, Model, Generation, or MarketTrim identities.

## Machine columns

The authoritative column inventory is generated from the live SpecRegistry by:

`automotive/vehicle_master/tools/export_vehicle_spec_template.py`

The generated workbook contains:

- `SPECS` — canonical trim rows and editable machine columns
- `FIELD_DICTIONARY` — field key, type, unit, powertrain applicability, qualifier names, and accepted ready columns
- `README` — fill rules

Normal registry fields use their exact keys, for example:

- `vehicle.seats`
- `vehicle.length_mm`
- `battery.usable_capacity_kwh`
- `safety.aeb`

A few MarketTrim-only fields use explicit `core.*` headers.

## Qualifiers

When a value needs context, that context is encoded in the header rather than guessed from the cell.

Common fixed aliases include:

- `range_nedc_km`
- `range_wltp_km`
- `range_cltc_km`
- `electric_range_wltp_km`
- `ground_clearance_unladen_mm`
- `dc_charge_10_80_min`

The generic form is:

`field.key__qualifier=value`

Use the generated `FIELD_DICTIONARY` instead of inventing a qualifier/header. A bare registry key is rejected when the field requires qualifier context.

## Cell semantics

- blank = no-op
- non-blank = parse and validate against the mapped canonical field
- invalid type/value = reject; never guess
- boolean accepts YES/NO, TRUE/FALSE, 1/0
- explicit value states: `UNKNOWN`, `NOT_AVAILABLE`, `NOT_APPLICABLE`
- `-` is rejected because its meaning is ambiguous

Field type, canonical unit, and powertrain applicability come from the live SpecRegistry.

## Source/evidence

The workbook does not provide source/evidence metadata. `observed_at` is generated by import infrastructure only for deterministic fact ordering; it is not a workbook field or source claim.
