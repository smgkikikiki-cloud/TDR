## Field-by-field reconciliation

The legacy column/form/operation descriptions below refer only to the read-only branch. The legacy implementation has `upcoming_cars`, `upcoming_car_updates`, `UP-####` IDs, server-side `isAdmin` + service-role actions, and a hard-delete path. Current `main` has no Upcoming Admin: `/upcoming` redirects to `/models`.

| --- | --- | --- |
| generated `id` and `vehicle_id` (`UP-0001`) | `id` UUID + public `slug` | Incompatible identity and URL model. Do not convert `UP-####` into a canonical vehicle ID. Slugs are editorial identifiers; canonical links use their own IDs. Legacy rows need an explicit mapping/redirect decision before any future import. |
| `vehicle_name` | `display_name`, `name_kind` (`OFFICIAL`, `WORKING`, `SEGMENT_CODE`) | Map the text only after selecting/confirming name kind. Public UI marks non-official names “ชื่อชั่วคราว”. The old form has no official-name evidence or name-kind selector. |
| no brand | `brand_text`, optional `brand_canonical_id` | Keep editorial display text distinct from an optional canonical brand link. Linking is reference-only; it must never create/edit a Vehicle Master brand. |
| no lifecycle field beyond `status` | `stage`: `RUMOR`, `REPORTED`, `OEM_TEASED`, `OEM_CONFIRMED`, `LAUNCH_DATE_SET`, `PRE_ORDER` | The old `RUMORED`/`CONFIRMED` enum cannot be renamed into these six stages without review. Admin must select the evidenced stage and record stage changes in history. |
| no separate lifecycle state | `state`: `ACTIVE`, `DELAYED`, `CANCELLED`, `LAUNCHED` | State is independent of stage and publication. `DELAYED` gets an amber indicator; cancelled entries are excluded from the list and may remain on detail for 90 days; launched entries leave the list and redirect to a linked canonical model. Year/half/quarter/month/day render in Buddhist era; ranges render both ends; override wins. Validate from ≤ to; DAY is a single exact date; any supplied precision requires `window_from`. Legacy conversion is lossy where its quarter/month/day implies no exact start date; do not invent one. |

## Proposed R0 Admin data contract (no writer implemented)

Admin edits one editorial `upcoming_vehicles` record with these logical groups:

1. **Identity:** `slug`, `display_name`, `name_kind`, `brand_text`; optional canonical brand/predecessor/launched model links. Canonical links resolve only existing records and remain references.
2. **Lifecycle:** `stage`, independent `state`, `thailand_scope`, `confidence`, `confidence_note`; append-only stage/state/publication events. Apply the six stage and four confidence enums above; enforce RUMOR ≤ MEDIUM and LAUNCH_DATE_SET/PRE_ORDER = CONFIRMED. Never conflate `status` (publication) with stage/state.
3. **Window:** optional precision-qualified inclusive `window_from`/`window_to`, plus display override. Validate coherent boundaries and render Buddhist-era labels; leave unknown values empty rather than infer them.
4. **Editorial estimates:** summary, body, segment, powertrains, production data and expected price range, all visibly labelled estimates; excluded from canonical and market systems.
5. **Evidence/rights:** source records with controlled kind and public visibility, `last_verified_at`; image path only with an allowed license and credit. No source means no publish. Private sources and internal notes never enter public response models.
6. **Publication/history:** `draft`/`published`, `published_at`, timestamps, stage history, and an append-only auditable event history. Unpublish/archive/delete behavior and retention must be owner-approved before R1.

The public DTO is a strict allowlist, never a raw database row: published + ACTIVE/DELAYED entries for P16; published details may show CANCELLED for the specified 90-day window; LAUNCHED is excluded from the list and redirects only when a valid canonical model reference exists. Filter `sources[]` to public sources before rendering, but retain only the approved aggregate source count. Do not serialize internal notes or private sources in HTML, JSON, OG, search indexes, or logs visible to anonymous users.

## R0 preview status and open owner decisions

The static P16/P17 previews intentionally use visible synthetic names, windows, stages, confidences and sources. They use no vehicle photographs, remote assets, live data or routes. Text specifications exist; there is no verified complete P16/P17 mockup or approved rendering. These previews are a review aid only.

Resolve before R1:

- Whether legacy `internal_notes` is retained privately, and the fate/retention of legacy free-text update messages.
- Whether every edit/publication/state transition must create an immutable event with author and before/after values; archive/purge permissions and history retention.
- Required proof, attribution text, expiry/territory fields and review responsibility for OWN/PRESS_KIT/LICENSED imagery.
- The allowed values and validation vocabularies for body type, segment, powertrain, production country/type and price currency/range.
- Exact allowed stage/state transitions; confidence-note visibility; window/date conversion of historical quarter/month data.
- Whether `state=LAUNCHED` without a canonical link is invalid (recommended: reject), and how public links/redirects behave if a canonical model is later retired.
- Migration authority reconciliation: current repo candidate v66 is not proof of the deployed migration ledger; recheck with explicit future authorization.

R0 acceptance authorizes neither schema work nor R1–R3. Current `/upcoming` redirect, P02/P05/P06 behavior, Admin, data, and production state remain unchanged.
