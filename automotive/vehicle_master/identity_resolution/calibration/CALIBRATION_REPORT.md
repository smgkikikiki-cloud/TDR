### What the unconfirmed-gap cap is made of

`SER_MISSING_ROW_SEMANTICS_UNCONFIRMED` counts every month of the 24-month window, inside both coverages, where at least one side has no row and that side's meaning of "no row" is unconfirmed. A month where **neither** source has a row (for example before a model launched) counts as a gap month just like a month where only one does, and a month where only TDR lacks the row stays a gap even if Ice later confirms zero. Of the 102 STRONG pairs that carry a gap:

| which side lacks the row in the gap months | STRONG pairs |
|---|---|
| both sources lack the row | 87 |
| only TDR lacks it | 10 |
| both sources lack the row + only TDR lacks it | 4 |
| both sources lack the row + only Ice lacks it | 1 |

* Gap months in total: 587 where both sources lack the row, 1 only Ice, 59 only TDR.
* 101 of the 102 pairs have **no** Ice-only gap month: for them Ice's answer to `Q-ICE-ABSENT-ROW` alone would not lift the cap, which is why the Ice-only what-if above changes nothing and only the Ice+TDR what-if does.

## 10. Limits of this report

* **The evaluator is a reference transcription of the SPEC, written by the same author** (`ref_eval_*.py`; it agrees with all 508 golden cases). Agreement proves consistency, not correctness; a rule that is wrong in the SPEC is wrong here.
* **Absent rows stay UNKNOWN** on both sides (invariant I4a). Ice has holes in 1109 of 1,200 groups (median 67 absent months), TDR in most models; every such month is excluded and counted as an unconfirmed-gap month, which caps AUTO. This is why far fewer groups reach AUTO than the old matcher produced.
* **TDR data shape.** 312 of 323 TDR models have a registrations series; 1 of 326 generations have an `ended` date, so the lifecycle veto can only act on launch dates; `body_type` is populated for 323 of 323 models. The last TDR month (2026-08) is a classless pivot month in the registrations pipeline (see `provider_capabilities.yaml` trace), which can understate class-dependent nameplates.
* **Volumes only order rows.** The tier cutoffs (`10,000` lifetime or `1,000` last-24-month units; `100` units for groups with no candidate; the "material change" tolerances) are prioritisation conventions in `review.py` / `pairs.py`, not policy.
* **A fresh evaluation, not a write plan.** The evaluator ran with no stored mappings, so it says what Contract v1 would conclude on this data, not what the write matrix would do to the existing R6 rows (that would be the I18 / protected-state logic, which has nothing to protect yet).
* **Extraction time.** The TDR side is as of 2026-10-11 02:55 UTC; the check in section 1 shows it equals the run's inputs.
* **Pairs are a selection.** The dataset keeps every legacy-stored, legacy-proposed and v1-relevant pair; plainly contradicting weak pairs are counted but not listed (`r6_calibration_groups.csv` has all 1,200 groups).
